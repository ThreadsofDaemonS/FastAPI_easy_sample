# FastAPI Easy Sample

A lightweight learning project that demonstrates, in real working code, most of the
topics from the `middle_python_django_interview_cheatsheet` (excluding the
Django-specific parts) plus Celery + RabbitMQ + Redis.

It's a small blog-style API: JWT register/login, posts with cursor pagination,
Redis-cached post list, and a background notification task via Celery/RabbitMQ.

## Stack

FastAPI · SQLAlchemy 2.0 (async) · PostgreSQL · Alembic · Redis · Celery · RabbitMQ · pytest

## Quick start (Docker)

```bash
cp .env.example .env
docker compose up -d --build

# first migration (autogenerated, since the DB is already up)
docker compose exec api alembic revision --autogenerate -m "init"
docker compose exec api alembic upgrade head
```

API: http://localhost:8000/docs
RabbitMQ management UI: http://localhost:15672 (guest/guest)

## Running locally without Docker (for development/tests)

```bash
python -m venv .venv
.venv\Scripts\activate       # Windows
pip install -r requirements.txt

pytest                       # tests need no real Postgres/Redis/RabbitMQ
```

Tests spin up an in-memory SQLite instead of Postgres, fakeredis instead of Redis,
and Celery runs in `task_always_eager` mode (no RabbitMQ needed) - external
boundaries of the system are mocked, not the business logic itself
(`tests/conftest.py`).

## Structure

```
app/
  main.py            FastAPI app, middleware, exception handlers
  config.py          pydantic-settings config
  database.py        async engine/session, Base, get_db
  models.py           SQLAlchemy models (User, Post) + indexes
  schemas.py          Pydantic input/output schemas
  security.py          password hashing (bcrypt), JWT
  deps.py               Depends: get_db, get_current_user, service factories
  exceptions.py          domain exceptions + exception handlers
  repositories.py         data access (SQLAlchemy select/update)
  services.py               business logic (UserService, PostService, EmailSender Protocol)
  cache.py                   Redis cache decorator + invalidation
  pagination.py                cursor/keyset pagination helpers
  utils.py                      generator (CSV export), Timer context manager
  celery_app.py                  Celery app (RabbitMQ broker, Redis backend)
  tasks.py                        Celery tasks
  routers/
    users.py                        /users/register, /login, /me
    posts.py                        /posts CRUD, cursor pagination, export, notify
alembic/               migrations (async env.py)
tests/                  pytest + httpx AsyncClient, fakeredis, celery eager mode
```

## Key endpoints

- `POST /users/register` - registers a user, sends a welcome email via `EmailSender`
- `POST /users/login` - OAuth2 password flow, returns a JWT access token
- `GET /users/me` - current user (requires `Authorization: Bearer <token>`)
- `POST /posts/` - create a post (auth required), invalidates the list cache, queues a Celery notification task
- `GET /posts/?limit=&cursor=` - cursor pagination, cached in Redis for 30s
- `GET /posts/{id}` - post details, atomically increments `views`
- `GET /posts/export` - CSV stream (generator, doesn't buffer the whole result in memory)

## Known simplifications (deliberate, since this is a learning project)

- No refresh tokens or a revocation list - just a short-lived access token.
- No rate limiting - though Redis is a great fit for it (`INCR` + `EXPIRE`).
- The autogenerated Alembic migration isn't committed to the repo - it's generated
  locally, since autogenerate needs a running DB and a committed migration would
  drift from the models anyway.
